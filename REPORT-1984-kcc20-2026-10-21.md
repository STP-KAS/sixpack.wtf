## What the prompt asked, and what changed

The job was a Testnet-10 KCC-20 rail for the 1984 square. The name LUMBRIDGE stays. One covenant family per rail. POCencept first, then KUSDT. OLAF stays off the public mint desk. tKAS stays the native coin. The tick 1984 is not a token.

Adaptations, each one because the sources said something the prompt did not:

- The pin is kccs main `1ed87aef`, which contains KCC-20 Final `9dec4a04`. The prompt’s “or main tip” is that commit.
- Final status alone does not change the spec body, so it does not by itself require a new mint. This square had no KCC-20 covenant, so the rails below are new genesis groups.
- Mint authority is not in KCC-20. `kcc-0020.md` §4 allows a covenant-specific entrypoint. `1984/covenant/authority_mint.ag` requires a Schnorr signature from an authority key, and it can rotate or renounce. The reference `PublicMint` in argent-lang/kcc20-reference `27f8403f` stays permissionless. The KCC20 actor is unchanged from `c8a08711`.
- The prompt asked for BLAKE3 of the tick as the extension. The three published constants below are not that hash for the names that were tried. The preimage was not recovered. The files record the bytes and do not invent a preimage.
- KCC-23 is still Draft. The preparation payloads follow that draft: version-1 transaction, payload `0x00` then UTF-8 JSON, no BOM, no trailing newline, keys in the order name, symbol, decimals. Genesis spends preparation output 0. If the draft changes, those names may need an update. The official KCC-23 Rust verifier was not run. The evidence is the payload shape plus node acceptance.
- Borrowed-receive schemes `0x01`, `0x02`, and two successive `0x03` links were not broadcast. `rotate` and `renounce` were not broadcast. Both exist in the local program and in the offline checks.
- The pages name the covenant ids. The shop, the bank, and an open-name mint stay on the square ledger and on SquarePeg locks. The site is static. It does not read the private node. A browser read of covenant state needs a public RPC, and moving the shop onto these covenants would strand locks that already exist.

## Cap

100000000 base units. 2 decimals. Displayed 1000000.00. That is the cent scale the square already uses for a price. It is not the off-chain ledger and not a dollar. The per-mint limit equals the cap, so a mint of the whole cap after any earlier mint fails on the remaining supply. Genesis holds authority outputs and the token seed only. No premine, no airdrop, and no balance copied from the square ledger.

Recipients on these two rails start with borrow scheme disabled (`0x00`). `kcc-0020.md` Security Considerations: an amount-threshold of 0 lets any party change the outpoint.

## Checker and programs in this repo

- `1984/kcc20.mjs` follows `kcc-0020.md` on `1ed87aef`. `borrowedReceive` is the §5 state-pair rule. `familyTotal` checks non-negative amounts, one extension, equal totals, and the §2 cap of `2^63 - 1`. A borrowed receive does not require the pair to conserve amount: the copied accept case goes from 1000 to 1501, and `familyTotal` is what stops a mint. `holderMint` and `requireIncrease` are square rules. They are not borrowed receives. KCC-20 does not define them.
- `1984/kcc-0020/vectors/conformance.json` is copied from kaspanet/kccs `1ed87aef`. SHA256 `9b424c96ea0e0093cacfd98e3013fd5cbf93dd149cb27696acf288510133010b`. The source note is beside the file. Placeholder signatures are not checked here. `signatureVerified` has to be strictly true for schemes `0x02` and `0x03`.
- `1984/covenant/kcc20.ag` and `token_seed.ag` are the reference actors at `27f8403f`. `authority_mint.ag` is the covenant-specific minter. `1984/covenant/poc/` and `1984/covenant/kusdt/` hold `kcc20.json` and a path-stripped `artifact.json`. The compiler’s local paths are not in those copies.
